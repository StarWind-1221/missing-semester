## 1. 代码检查

1. Code formatter：主动对代码的格式进行调整，例如：缩进、空格、字符串偏好单引号还是双引号
2. Editorcofig: 方便不同的编辑器（VS Code, Vim）写出的代码保持相同的风格

3. Linter: 静态代码分析器（不运行代码）
4. `semgrep`：semantic 层面的检查，比正则表达式更加灵活



## 2. 测试

基本测试：给定输入，判断输出是否符合预期

另一种测试：基于属性的测试，比如每个字符串、整数，应当满足什么. 感觉是基于数据类型进行的测试

一种衡量标准：代码覆盖率，已测试的代码占总代码的比重



## 3. Pre-commit hooks （钩子）

在 `git commit` 之前进行代码检查



## 4. Command Runner

## 5. Hatch and Ruff

### 🛠️ Hatch：Python 项目管理器
Hatch 的定位是“现代、可扩展的 Python 项目管理器”。它处理的是项目层面的工作，主要功能包括：
*   **环境管理**：创建和管理虚拟环境，运行测试或脚本。
*   **构建与发布**：提供标准化的构建系统，方便将包发布到 PyPI。
*   **版本管理**：帮助管理项目的版本号。
*   **静态分析入口**：提供 `hatch check code` 和 `hatch check fmt` 等命令，用于代码检查与格式化。

### ⚡ Ruff：极速代码检查器与格式化器
Ruff 专注于代码层面的质量检查。它的核心优势是**速度**。
*   **代码检查 (Lint)**：通过 `ruff check` 命令，检查代码中的错误、风格问题等，支持超过 900 条规则。
*   **代码格式化 (Format)**：通过 `ruff format` 命令，自动调整代码格式。

### 🔗 两者的关系：Hatch 调用 Ruff
当使用 Hatch 的静态分析命令（如 `hatch check code`）时，Hatch 实际上是在调用 Ruff 来执行检查任务。

Hatch 做的主要工作是提供一套**预设的、更严格的 Ruff 配置**。例如，Hatch 默认将行长度限制设为 120（而 Ruff 默认是 88），并启用了更多的检查规则。这样做的好处是，开发者无需自己从头编写复杂的 Ruff 配置文件，就能在 Hatch 项目中获得一套开箱即用的高标准代码规范。

Hatch 负责管理项目和环境的“大局”，而 Ruff 则作为其内部的一个高效“质检员”，负责具体的代码检查与格式化工作。
